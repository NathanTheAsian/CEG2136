       CEG 2136: Computer Architecture I

           Laboratory 3: Design and Simulation of ALU

1 Objective

This laboratory requires students to design and simulate the execution unit (datapath) of
a Central Processing Unit (CPU). Students will complete the following tasks:

    · Design a 4-bit execution unit comprised of an arithmetic and logic circuit.
    · Implement 16 distinct microoperations that process two 4-bit operands.
    · Derive and implement status register logic to track overflow (V), zero (Z), negative

       (N), and carry (Cy) conditions.
    · Simulate the complete datapath using a provided input generator to supply the

       operands (A, B) and control signals (S3 . . . S0).
    · Download and run the design on the Altera DE2-115 board to experimentally verify

       the circuit.
Textbook: Computer System Architecture, Morris Mano, 3rd Ed.
Recommended Reading: Section 2.4 (Registers), Section 3.3 (Fixed-Point Representa-
tion), and Chapter 4 (Register Transfer and Microoperations)

2 Introduction

A Central Processing Unit (CPU) consists of two primary components: a control unit (CU)
and an execution unit (EU), also known as the datapath. In this laboratory, students design
the datapath to process two 4-bit operands and generate a 4-bit result.

                                                         1
       Figure 1: CPU block diagram - Control Unit (CU) and Execution Unit (EU).

2.1 Functional Specification

The datapath stores data in buffer registers (D flip-flops). Register A and Register B
hold the incoming operands, while Register C stores the final output. The system is
synchronous; because all D flip-flops are driven by the same clock signal, the reading of
inputs and the writing of outputs occur within the same clock cycle.

    The Arithmetic Logic Unit (ALU) operates as a combinational circuit capable of exe-
cuting 16 distinct operations. A 4-bit control signal (S3 . . . S0) dictates the operation:

    · Mode Select (S3): Routes the operands to either the Arithmetic Circuit (AC) or
       the Logic and Shift Circuit (LSC).

    · Operation Select (S2 . . . S0): Defines the specific arithmetic or logical operation
       performed within the selected circuit.

    The system evaluates the ALU output to generate four status flags: Overflow (V), Zero
(Z), Negative (N), and Carry (Cy).

               Figure 2: Block diagram of the datapath with input_generator.
    To facilitate testing and simulation, the design incorporates a pre-designed component
named input_generator_high_freq. This module automatically generates the sequence
of test vectors for the operands (A, B) and the control signals (S), as illustrated above in

2.2 Relevance to Computer Architecture

The datapath is the core execution unit of a processor, responsible for performing micro-
operations on register data [3]. Designing the arithmetic and logic circuits as distinct,
modular blocks reduces hardware complexity. Selector signals then route the appropriate
result to the final output. Finally, status bits (V, Z, N, Cy) provide immediate feedback
to the control unit, enabling the processor to evaluate data conditions (e.g., arithmetic
overflow) and adjust its control flow accordingly [3].

3.3 ALU Status Register Equations

Derive the logic equations for the four status bits. Implement them using conventional
logic gates based on the following functional definitions:

    · Cy (Carry): Set to 1 only when the operation is an arithmetic operation and its
       carry output is 1.

    · N (Negative): Set to 1 if the most significant bit of the result (C3) is 1.
    · Z (Zero): Set to 1 only if the output of the ALU contains all 0's.

                                                         6
    · V (Overflow): Set to 1 when an overflow occurs during 2's complement opera-
       tions. For this lab, implementing overflow detection for signed arithmetic (addi-
       tion/subtraction) is sufficient. Handling overflow for shift operations (e.g., arithmetic
       shift left) is optional.

A Appendix I: Best Practices and Troubleshooting

Use the following references and techniques to guide your laboratory work.

A.1 Project Organization

Always create dedicated folders for each Quartus project. Because laboratory computers
erase local files when powered off, you must save and back up your project folders using
your University OneDrive to prevent data loss.

A.2 Debugging Connections

To verify signal connectivity in the schematic editor, double-click a wire segment. Quartus
highlights the entire connected net, as shown in Figure 13, allowing you to confirm that
an input is connected to its intended destination.

  Figure 13: Quartus highlighting a connected net upon double-clicking a wire segment.

A.3 Naming Wires

Name wires to make Quartus recognize connections without drawing the entire physical
path [1], as shown in Figure 14.

          Figure 14: Named wires create logical connections without physical lines.

A.4 Using Bus Connections

Replace multiple individual wires with bus connections to simplify complex schematic
designs. Buses reduce visual clutter and lower the probability of wiring errors when routing
multiple inputs and outputs. This practice becomes critical as circuit designs grow.

    A bus carries multiple data bits. A bus of three signals utilizes the naming format
X[2..0] (count down). In Quartus, buses appear as thick wires. You can extract individual
signals from buses and use them as regular inputs [4], as shown in Figure 15.

     Figure 15: Bus in Quartus, X[2..0], with individual signals used as regular inputs.

A.6 Simplifying Simulation Analysis

In the waveform editor, group related input or output signals together. Select multiple
inputs, right-click, choose Grouping, and select Group.

    Once grouped, the radix (base) of the group can be modified. Right-click the group,
select Radix, and choose binary, hexadecimal, unsigned decimal, or octal. This allows you
to input and read values as single numbers (e.g., A = 1011), which speeds up verification,
as shown in Figure 18. When grouping signals, ensure that the bits are ordered from most
significant bit (MSB) to least significant bit (LSB) [1].

                Figure 18: Grouped input signals utilizing a hexadecimal radix.
    Note: If bus connections are used in the schematic, Quartus automatically groups these
signals in the waveform editor.

A.7 Quartus Software Glitches (Simulation or Compilation)

Occasionally, Quartus workspace files can become corrupted. You might be experiencing
this if:

    · The simulation window opens and immediately closes without displaying any wave-
       forms.

    · The compilation process gets completely stuck, freezes, or runs unusually slowly.
Solution: Create a brand new Quartus project in a new folder. Copy over only your
essential source files (such as your .bdf, .bsf, .v, .vhd, and .vwf files) into the new
project and recompile.

                                                        19
A.8 Hardware Connection Issues (USB-Blaster)

When attempting to program the FPGA, the USB-Blaster might occasionally fail to appear
in the list of available hardware. Try the following:

   1. Close and reopen the Hardware Setup window in the Programmer.
   2. Unplug and replug the USB cable connecting the board to the PC.
   3. Power-cycle the DE2-115 board (turn the red power button off, wait a few seconds,

       and turn it back on).
Solution: If the USB-Blaster still fails to connect after trying all of the above steps, the
specific test board, cable, or PC USB port may be faulty. In this case, try moving to
another station and try again.
