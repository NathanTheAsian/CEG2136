Introduction
This final laboratory introduces the design and simulation of a Central Processing Unit
(CPU) based on a Reduced Instruction Set Computer (RISC) architecture. Specifically,
students will design a hardwired Control Unit (CU) capable of executing a full instruction
set.
While the fundamental structure parallels the BASIC computer architecture pre-
sented in the textbook [3], this implementation introduces some modifications to memory
formatting and instruction fetching that alter the control sequence.

2.1
Functional Specification
2.1.1
Memory Architecture and Instruction Length
The primary deviation from the textbook architecture is the memory organization. The
textbook uses a 4096×16 memory, allowing a complete 16-bit memory-reference instruction
(4-bit opcode combined with a 12-bit address) to fit entirely within a single location [3].
In contrast, this laboratory utilizes a 256 × 8 memory. Because a memory-reference
instruction remains 16 bits long, it must be stored across two consecutive 8-bit locations:
• Byte 1: The instruction opcode.
• Byte 2: The operand address (8 bits fully address the 256-word space).
Consequently, fetching a memory-reference instruction requires two consecutive READ
cycles: one to retrieve the opcode into the Instruction Register (IR), and another to
retrieve the address into the Address Register (AR).
2.1.2
The Instruction Cycle
The sequence counter (SC) behaves as a finite state machine, driving a decoder that gen-
erates distinct timing signals (T0 . . . T12).
A full cycle of Display →Fetch →Execute
processes exactly one instruction, provided the Stop Register remains low. The system
repeatedly executes this three-phase sequence:
1. Display: This phase operates continuously to allow real-time observation.
The
memory address defined by the external DIP switches is loaded from the OUTA register
into the Address Register (AR), and the corresponding memory content is routed to
the OUTD register for output to a 7-segment display.
2. Fetch: The CPU prepares for execution. Because memory is 8-bit, the Program
Counter (PC) guides multiple read steps. The CPU first fetches the opcode and
evaluates IR[7]. If it is a register-reference instruction, the fetching phase concludes.
If it is a memory-reference instruction, the PC increments, and the CPU initiates a
second read cycle.
• In direct addressing, this second byte holds the operand address, which is
directly read and loaded into the AR.
4
• In indirect addressing, this second byte holds a pointer to a memory location
that contains the actual operand address, requiring a third read cycle to retrieve
and load the final address into the AR.
Once the AR holds the final target address, the CPU is ready for execution.
3. Execute: The CPU performs the specific micro-operations designated by the X and
Y signals alongside the T timing states. Once execution concludes, the sequence
counter (SC) is reset to 0, signaling the start of the next full instruction cycle.
Notes:
• Memory Initialization: The processor memory is initialized using a file called
memorycontents8.mif.
This file defines the memory size, width, and the initial
machine code instructions required for the laboratory.
• System Halt: If the Stop Register is set to 1, it halts the incrementation of the PC
and stops program execution. However, the Display logic will continue to function.
2.1.3
Timing and Synchronization
Many Instruction Decoder outputs are Mealy-type signals, meaning they depend on both
the current state (T signals) and inputs (IR and DR contents) [3]. Asynchronous input
transitions during a clock cycle can cause transient logic glitches.
Therefore, directly
routing these unbuffered outputs to the datapath would result in errors. To resolve this, a
Control Register buffers the outputs, ensuring the commands are strictly synchronized to
the clock edge and stable for a full clock period before reaching the CPU components.
2.1.4
Instruction Format and Decoding
The control unit must interpret the bits stored in the Instruction Register (IR) to determine
the necessary micro-operations.
• Instruction Type (IR[7]): Distinguishes between memory-reference instructions
(IR[7] = 0), which interact with memory and require 16 bits, and register-reference
instructions (IR[7] = 1), which act directly on CPU registers and only require 8
bits.
5
• Addressing Mode (IR[6]): For memory-reference instructions, this bit determines
if the address provided is direct (IR[6] = 0) or indirect (IR[6] = 1), where the
fetched operand address serves as a pointer to the actual data location.

2.2
Relevance to Computer Architecture
In a CPU with multiple registers, creating individual paths between every register and
memory would require an excessive number of wires [3].
A more efficient scheme for
transferring information is to use a Common Bus System [3].
While a single shared bus greatly reduces physical wiring complexity, it introduces two
strict physical constraints that dictate how instructions must be executed:
1. The bus can only select one source at a time, transferring data to the designated
destination register during the clock pulse transition [3]. Thus, memory can perform
only one access (read or write) per clock cycle.
2. Any register can receive data from the bus except the Accumulator (AC) [3]. The
inputs of the AC come strictly from the adder and logic circuit (ALU) [3].
To accommodate these constraints, data cannot move directly to the AC and must instead
be routed through specific intermediate registers.
12
2.2.1
The Hierarchy of Registers
Each register in the datapath serves a distinct, non-interchangeable purpose, ensuring the
Control Unit (CU) and ALU receive stable inputs during the correct clock cycle:
• Program Counter (PC): The PC acts as an instruction pointer.
It holds the
memory address of the next byte to be fetched; it does not store actual instructions
or data.
• Address Register (AR): The memory address input is connected strictly to the
AR. Therefore, the AR must always be used to specify a memory address [3].
• Instruction Register (IR): Once an opcode is fetched, it is stored in the IR. This
allows the CU to continuously decode the instruction (X and Y signals) while the
rest of the datapath is available to fetch subsequent addresses or data.
• Data Register (DR): Because the AC cannot read directly from the bus, the DR
acts as a buffer. Data fetched from memory is held in the DR. The inputs from the
DR and AC are then used for arithmetic and logic micro-operations, and the result
is transferred back into the AC [3].
2.2.2
Translating Assembly
To understand how this hierarchy works in practice, consider the execution of a simple
assembly command: ADD 0x80 (Add the contents of memory address 0x80 to the Accu-
mulator).
1. Instruction Fetch: The CPU moves the current PC value to the AR (AR ←PC)
to point to the instruction in memory.
2. Opcode Decode: Memory outputs the opcode, which is loaded into the IR (IR ←
M[AR]). The CU decodes this as an ADD command.
3. Operand Address Fetch: The PC increments to point to the next byte (PC ←PC
+ 1). This new address is moved to the AR (AR ←PC) to fetch the target location.
Memory outputs 0x80, which is immediately loaded back into the AR since this is
direct addressing (AR ←M[AR]).
4. Data Fetch: With the AR now pointing to 0x80, memory outputs the actual nu-
merical operand. This operand is loaded into the DR buffer (DR ←M[AR]).
13
5. Execution: The ALU now has both required operands. It adds the value in the DR
to the current value of the AC, and writes the sum back into the AC (AC ←AC +
DR).

Appendix I: Best Practices and Troubleshooting
Use the following references and techniques to guide your laboratory work.
A.1
Project Organization
Always create dedicated folders for each Quartus project. Because laboratory computers
erase local files when powered off, you must save and back up your project folders using
your University OneDrive to prevent data loss.
A.2
Debugging Connections
To verify signal connectivity in the schematic editor, double-click a wire segment. Quartus
highlights the entire connected net, as shown in Figure 3, allowing you to confirm that an
input is connected to its intended destination.
Figure 3: Quartus highlighting a connected net upon double-clicking a wire segment.
23
A.3
Naming Wires
Name wires to make Quartus recognize connections without drawing the entire physical
path [1], as shown in Figure 4.
Figure 4: Named wires create logical connections without physical lines.
A.4
Using Bus Connections
Replace multiple individual wires with bus connections to simplify complex schematic
designs. Buses reduce visual clutter and lower the probability of wiring errors when routing
multiple inputs and outputs. This practice becomes critical as circuit designs grow.
A bus carries multiple data bits. A bus of three signals utilizes the naming format
X[2..0] (count down). In Quartus, buses appear as thick wires. You can extract individual
signals from buses and use them as regular inputs [4], as shown in Figure 5.
Figure 5: Bus in Quartus, X[2..0], with individual signals used as regular inputs.
24
Figure 6: Flip-flop alternate design utilizing bus connections for inputs and outputs.
A.5
Using Wires
In Quartus schematic entry (.bdf) files, you can use a wire primitive to assign multiple
names to the same signal [4], as illustrated in Figure 7. A wire primitive looks like an
inverter without the bubble.
Figure 7: Wire primitive assigning multiple names to a single signal.
25
A.6
Simplifying Simulation Analysis
In the waveform editor, group related input or output signals together. Select multiple
inputs, right-click, choose Grouping, and select Group.
Once grouped, the radix (base) of the group can be modified. Right-click the group,
select Radix, and choose binary, hexadecimal, unsigned decimal, or octal. This allows you
to input and read values as single numbers (e.g., A = 1011), which speeds up verification,
as shown in Figure 8. When grouping signals, ensure that the bits are ordered from most
significant bit (MSB) to least significant bit (LSB) [1].
Figure 8: Grouped input signals utilizing a hexadecimal radix.
Note: If bus connections are used in the schematic, Quartus automatically groups these
signals in the waveform editor.
A.7
Quartus Software Glitches (Simulation or Compilation)
Occasionally, Quartus workspace files can become corrupted. You might be experiencing
this if:
• The simulation window opens and immediately closes without displaying any wave-
forms.
• The compilation process gets completely stuck, freezes, or runs unusually slowly.
Solution: Create a brand new Quartus project in a new folder. Copy over only your
essential source files (such as your .bdf, .bsf, .v, .vhd, and .vwf files) into the new
project and recompile.
26
A.8
Hardware Connection Issues (USB-Blaster)
When attempting to program the FPGA, the USB-Blaster might occasionally fail to appear
in the list of available hardware. Try the following:
1. Close and reopen the Hardware Setup window in the Programmer.
2. Unplug and replug the USB cable connecting the board to the PC.
3. Power-cycle the DE2-115 board (turn the red power button off, wait a few seconds,
and turn it back on).
Solution: If the USB-Blaster still fails to connect after trying all of the above steps, the
specific test board, cable, or PC USB port may be faulty. In this case, try moving to
another station and try again.
